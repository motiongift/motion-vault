## Behaviour

An idempotent ATA-create instruction does not prove a new account needs rent. Sell preflight used to count every such instruction and could reject 0.0045 SOL as needing about 0.0073 SOL before simulation, even for existing accounts. Sells now preflight fees only; the existing simulation pays the worst-case trial priority charge and checks actual account rent before any signature. The post-simulation balance guard adds back the trial priority fee and subtracts the rounded-up final fee once. Buy arithmetic and trial priority are unchanged.

Only jupiterTradeOne changed in the frozen source. No extra RPC, await, automatic retry, key-storage or send change. Owner approval is recorded in docs/SOL-SELL-RENT-APPROVAL-2026-11-08.md and the trade-core pin fixture.

## Limits

Genuine SOL insufficiency still fails before signing. The conservative maximum-CU trial priority budget can refuse a transaction whose final lower-CU charge might be affordable. Existing nominal-rent tolerance inside the final balance guard is unchanged; this is an affordability correction, not a redesign of that guard. State may change after simulation.

## Delivery and verification

The build stays at local server/web/vendor/engine.js for reproducibility. npm run release makes an immutable /vendor/engine-<sha256>.js copy and binds that exact URL and SRI in vault.html and releases.json. npm run verify follows the restricted engine.file path in the manifest and hashes its fetched bytes. Existing signer/frame metadata is preserved.

Production retains the old canonical /vendor/engine.js bytes so already-delivered old HTML remains valid. Deploy only the new immutable file, HTML and manifest, with matching exact nginx allowance. Do not overwrite the old canonical URL through generic static-sync. Rollback restores the old HTML/manifest but keeps the new versioned file and route for already-open tabs. No RPC hosts or CSP connection policies change.
